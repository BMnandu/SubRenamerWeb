# 版本与标签规范

## 版本号

公开稳定版本遵循语义化版本 `MAJOR.MINOR.PATCH`：

- `MAJOR`：存在明确不兼容变更；
- `MINOR`：向后兼容的新功能；
- `PATCH`：向后兼容的问题修复。

当前只发布稳定版本标签。预发布版本需要时再单独扩展规范和镜像策略。

## Git 标签

- 格式固定为 `vMAJOR.MINOR.PATCH`，例如 `v1.1.0`。
- 必须使用附注标签（annotated tag），标签说明固定为 `SubRenamerWeb vMAJOR.MINOR.PATCH`。
- 标签只能指向已合并到 `main`、且主分支全部门禁通过的提交。
- 已推送的公开标签不可移动、覆盖或删除；需要修复时发布新的 PATCH 版本。
- 历史 `v1.0.0` 已是附注标签，保持原状，不重写历史。

创建示例：

```bash
git switch main
git pull --ff-only
git tag -a v1.1.0 -m "SubRenamerWeb v1.1.0"
git push origin v1.1.0
```

## Docker 标签

Git 标签中的前缀 `v` 不进入 Docker 标签。推送 `v1.1.0` 后发布：

- `beiming712/subrenamerweb:1.1.0`：精确版本，可用于固定部署；
- `beiming712/subrenamerweb:1.1`：同一 MINOR 版本的最新 PATCH。

`main` 和 `latest` 由主分支发布流程维护，不等同于不可变版本标签。生产部署若需要可重复回滚，应优先固定完整版本 `1.1.0`，不要只使用 `latest`。

## 发布边界

- 创建 Git 标签会触发公开 Docker 多架构镜像发布。
- 镜像发布不代表 NAS 或媒体库已经部署。
- GitHub Release 可按需创建，但正文必须与 `CHANGELOG.md` 对应版本一致。
