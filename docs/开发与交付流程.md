# 开发与交付流程

## 1. 权威来源

- 项目目标、版本范围和验收标准：个人项目目录中的版本规划文档。
- 当前实现和历史：Git 仓库、目标提交和 Pull Request。
- 生产运行状态：真实部署核验记录；PR 合并不等于已经部署。

开始任务前必须记录基线提交，并确认工作区没有来源不明的改动。

## 2. 分支约定

禁止直接在 `main` 上开发。每个任务建立独立分支：

| 类型 | 分支示例 |
|---|---|
| 功能 | `feat/sync-plan` |
| 修复 | `fix/path-boundary` |
| 重构 | `refactor/sync-runner` |
| 测试 | `test/sync-workflow` |
| 文档/工程 | `docs/api-migration`、`chore/development-foundation` |

一个分支只解决一个可验收主题。v1.1.0 应拆成多个可独立评审的 PR，不使用长期堆积的大分支。

## 3. 推荐实施顺序

1. 从版本规划提取本 PR 的范围、非目标和验收条件。
2. 为缺陷或安全边界先增加失败测试。
3. 实现最小改动，使测试通过。
4. 执行格式、构建、测试及必要的 Docker/端到端验证。
5. 自审文件写入、路径、日志、异常和兼容性。
6. 更新中文 README、API 或迁移文档。
7. 创建 PR，等待 CI 通过后再合并。
8. 合并后返回提交、PR、测试和未部署声明，供项目文档核验。

## 4. 本地验证门禁

基础门禁：

```bash
dotnet restore SubRenamer.Web.sln
dotnet build SubRenamer.Web.sln -c Release --no-restore
dotnet test SubRenamer.Web.sln -c Release --no-build --filter "Category!=EndToEnd"
```

容器相关改动额外执行：

```bash
docker build -t subrenamerweb:local-test .
```

调轴实现改动还必须执行可重复的 FFmpeg + FFsubsync 端到端测试：

```bash
python3 -m venv .venv-e2e
.venv-e2e/bin/python -m pip install "ffsubsync==0.5.1"

RUN_REAL_SYNC_E2E=1 \
PYTHON_EXECUTABLE="$PWD/.venv-e2e/bin/python" \
FFMPEG_EXECUTABLE=ffmpeg \
dotnet test tests/SubRenamer.Web.Tests/SubRenamer.Web.Tests.csproj \
  -c Release \
  --filter "Category=EndToEnd"
```

该测试通过 FFmpeg 动态生成短视频，真实调用 Python wrapper 与 FFsubsync，并验证调轴偏移、staging、commit 和 rollback。CI 中的 `Real FFmpeg + FFsubsync E2E` 作业会强制启用；任何未执行的命令都要在 PR 中明确写出，不能描述为“已通过”。

## 5. PR 与合并门禁

PR 至少包含：

- 变更摘要和关联规划；
- 实际测试命令及结果；
- API、配置、数据或文件行为的兼容性说明；
- 安全影响和已知限制；
- “未执行生产部署”的明确声明。

必须通过 `CI / Build and test`、`CI / Docker build` 与 `CI / Real FFmpeg + FFsubsync E2E`。发布镜像的 workflow 只负责发布，不替代 PR 校验。

## 6. v1.1.0 建议拆分

为降低安全重构风险，按以下顺序推进：

1. `SafePathService` 与路径/符号链接测试；
2. 唯一输出命名与调轴计划模型；
3. staging、manifest 和逐项任务状态；
4. FFsubsync 结构化执行器、质量门禁、超时与取消；
5. commit、冲突处理、备份和 rollback；
6. 队列、并发、过期清理和 API；
7. WebUI 工作流与旧 API 迁移层；
8. 真实端到端 fixture、容器验证和中文文档。

每一步都应保持扫描、上传和匹配能力可用，并为下一步提供稳定接口。

## 7. 发布和生产边界

- `main` 合并可以触发镜像构建，但不授权部署到家庭环境。
- 版本标签只能在目标验收完成后创建。
- 不在仓库中保存 Docker Hub Token、NAS 凭据或真实媒体路径。
- 部署、媒体库写入和生产验证必须取得单独授权并留下可核验证据。
